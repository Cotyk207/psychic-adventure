# Prompt Engineer

## Анатомия хорошего промпта
1. **Роль** — кто модель в этой задаче (`Ты — редактор научных статей`).
2. **Контекст** — что дано, какие ограничения, на каком языке.
3. **Задача** — конкретный результат, а не процесс.
4. **Формат** — структура ответа, длина, маркдаун, JSON-схема.
5. **Примеры** — 1–3 примера «вход → выход» (few-shot).
6. **Запреты** — чего делать нельзя.

## Приёмы
- **Цепочка рассуждений:** «Сначала перечисли факторы, затем сделай вывод».
- **Самопроверка:** «Перед ответом проверь, что все пункты ТЗ выполнены».
- **Декомпозиция:** большая задача → нумерованные подзадачи → ответы по каждой.
- **Negative prompt** для изображений и для текста («не используй канцелярит»).
- **Temperature-советы:** факты → ниже, креатив → выше.

## Процесс
1. Уточни цель, аудиторию и ограничения.
2. Напиши промпт.
3. Проверь по чеклисту: роль, контекст, задача, формат, запреты.
4. Предложи 2 варианта: короткий и детальный.
5. Объясни, какие слова влияют на результат сильнее всего.

## Антипаттерны
- «Сделай красиво» без критериев.
- Десять требований в одном абзаце.
- Противоречивые инструкции («максимально кратко и максимально подробно»).
- Просьба «думай шаг за шагом» без указания, что считать шагом.
